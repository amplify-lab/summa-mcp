# Summa 免費會計助手（summa-tw-accounting）

> 會計、稅務、薪資的專業助手

> Free MCP server for Taiwan accounting, tax and payroll — answers cite official sources (Traditional Chinese).

## 這是什麼

Summa 免費會計助手是會計、稅務、薪資的專業助手，也是讓 AI 助理查台灣會計、稅務與薪資資料的免費 MCP 伺服器：記帳做法、稅率與門檻、申報期限、代碼、法規全文、試算，以及加班費、勞健保勞退、特休、資遣費的計算。每筆結果附官方出處、生效日與查證日。給記帳的老闆、會計、出納、記帳士，以及任何用 Claude 或其他 AI 處理台灣帳務的人。

連線網址：`https://mcp.summa.com.tw/mcp`（公開、不用登入、只讀）

資料與工具都在伺服器端更新：法規修正、新工具、記帳做法補強上線後，已經安裝的人不用重裝或升級，下一次對話就會用到新版。

## 安裝

最快的方法：把這個 repo 的網址貼給你的 AI（Claude、Claude Code 或 ChatGPT），跟它說「幫我裝這個」，它會照 [INSTALL.md](INSTALL.md) 的步驟做，需要你按的地方會一步一步告訴你。

### Claude Code

```
claude mcp add --transport http summa-tw-accounting https://mcp.summa.com.tw/mcp
```

### Claude 網頁版與桌面版

設定 → Connectors → 新增自訂連接器，名稱填「Summa 免費會計助手」，網址填 `https://mcp.summa.com.tw/mcp`，不用登入。

### ChatGPT

1. 只有網頁版，Plus、Pro、Business、Enterprise、Edu 可以用；Business、Enterprise、Edu 要管理員開放。
2. 設定 › 安全與登入（Security and login）› 打開「開發者模式」（Developer mode）。
3. 到 Plugins（chatgpt.com/plugins）按＋，新增開發者模式的 app：名稱「Summa 免費會計助手」，網址 `https://mcp.summa.com.tw/mcp`，驗證選「不需驗證」（No Authentication）。
4. 對話時從輸入框的＋選單打開開發者模式，選這個 app。

方案與選單以 OpenAI 目前的說明為準（[開發者模式說明](https://developers.openai.com/api/docs/guides/developer-mode)），畫面可能調整。

### 其他 MCP 用戶端

加一個 streamable HTTP 類型的伺服器，網址 `https://mcp.summa.com.tw/mcp`，不用驗證。

### 範例：放進你的產品（function tool）

[`examples/saas_voucher_draft.py`](examples/saas_voucher_draft.py) 是一個電商 SaaS 後台的例子：你自己的撥款資料是一支 function tool，Summa 的工具透過 Anthropic Python SDK 的 MCP 轉換，也變成 function tool，模型一起使用，產出傳票草稿交給會計審核。

```python
@beta_async_tool
async def get_payout(payout_id: str) -> str:
    """讀取電商平台的撥款明細（訂單金額、平台手續費、實際撥款）。"""
    ...  # 從你的資料庫或平台 API 讀

async with streamable_http_client("https://mcp.summa.com.tw/mcp") as (read, write):
    async with ClientSession(read, write) as mcp:
        await mcp.initialize()
        summa_tools = [async_mcp_tool(t, mcp) for t in (await mcp.list_tools()).tools]
        runner = client.beta.messages.tool_runner(
            model="claude-opus-5-5",
            max_tokens=16000,
            system=SYSTEM,  # 記法與數字先查 Summa 工具；草稿交會計審核
            tools=[get_payout, *summa_tools],
            messages=[{"role": "user", "content": "撥款單 P-20261015-001 入帳了，幫我做傳票草稿。"}],
        )
        async for message in runner:
            ...
```

- 需要 Python 3.10 以上、`pip install "anthropic[mcp]"`、你自己的 `ANTHROPIC_API_KEY`。
- 不想自己處理工具呼叫，也可以用 Claude API 的 MCP 連接器：請求帶 `mcp_servers`（網址填上面那個）加一個 `mcp_toolset`，由 Anthropic 代為連線。
- 其他模型（例如 OpenAI）也一樣：用 MCP 用戶端取得工具清單，轉成該家的 function 定義，模型要呼叫時轉給這個 MCP。
- 模型給的是草稿：入帳、申報前由會計或記帳士確認。

| 其他 | 產業創新條例、行政程序法（期限遇假日順延）、個人資料保護法、記帳士法等 |

**會計準則與項目表**
- 商業會計法、商業會計處理準則：全文收錄，記帳做法照它們寫（例：記帳錯誤影響總數的另開傳票更正，處理準則第 13 條）。
- 企業會計準則公報（EAS）：全文有著作權，不收全文；只收號次與主題對照，引用到條號（例：前期錯誤更正 EAS 第 4 號第 15、19 條），需要判斷重大性、實務上不可行的，寫「請會計師判斷」。
- 經濟部商業會計項目表：112 年度與 117 年度兩版對照（代碼、名稱、正常餘額、變動）。

**函釋與官方表**
- 常見判斷與函釋 37 段，附字號；只查到要旨、沒有原文的，寫明是依國稅局或公會引述。
- 財政部：115 年度薪資所得扣繳稅額表、固定資產耐用年數表、營業人開立銷售憑證時限表。
- 勞動部：最低工資公告、加班費與資遣費試算器的算法（倍率用分數、無條件進位）、月薪 ÷ 30 ÷ 8 與休息日按實際時數的函釋、天然災害出勤管理及工資給付要點。
- 勞保局、健保署：115 年勞保投保薪資分級表與分擔金額表（按投保日數）、健保投保金額分級表與負擔金額表、勞退月提繳分級表。
- 勞動部、勞保局：勞工職業災害保險適用行業別及費率表（114 年 1 月 1 日起適用，行業類別編號 1 至 55，代碼 `occupational_industry_rate`）；勞工職業災害保險投保薪資分級表（115 年 1 月 1 日施行，21 級，代碼 `occupational_insurance_grade`）。
- 行政院主計總處：國外出差日支數額。

**記帳的固定做法**（`bookkeeping_guide` 每次都回）
- 先確定原始憑證是什麼，再寫傳票；每張傳票借貸相等，金額一律整數元。
- 控制科目（應收、應付、預收、預付、暫收、暫付、代收）的每一行帶往來對象，寫明開新項目還是沖哪一個。
- 稅額以一張發票為單位算，不逐行加總再算稅。
- 已過帳的傳票不改不刪，錯了另開傳票更正（沖銷加重開，或只調差額）；發票造成的傳票從發票改（作廢或折讓）。
- 作廢、折讓、進項、營業稅的題目，寫明 401 填在哪一期、哪一類。

**算錢的固定做法**（`payroll_guide` 與各支試算）
- 先判斷計薪方式（時薪、日薪、月薪）與那一天的種類（平日、休息日、例假、國定假日、天災）。
- 月薪制平日每小時工資額＝月薪 ÷ 30 ÷ 8，經常性給與要算進去。
- 法條寫「加給以上」的倍率用分數（4/3、5/3、8/3）算，最後無條件進位到元，跟勞動部試算器一致。
- 勞保、健保不自己乘費率，直接用官方金額表（勞保、就保各自算到元再相加；健保雇主按平均眷口數 0.56）。
- 好幾天、好幾段的分別算再加總；題目缺條件時，列出缺什麼，每一種情況都算出金額。

**判斷題**
- 事實不明時，每個分岔都寫完整結論與條號；只有法條、沒有函釋的個案，給有條件的結論並寫明查不到。
- 不提供規避或逃漏的做法，改寫合規的做法。

## 我們記什麼、不記什麼

為了知道有多少人在用、哪些工具有用，伺服器記匿名的使用統計（Cloudflare Workers Analytics Engine）：

| 記 | 不記 |
|---|---|
| 日期（台北時間） | 你問的問題、對話內容 |
| 事件：連線（initialize）或呼叫工具 | 工具的參數值（金額、日期、條號、代碼都不記） |
| 你的 AI 用戶端名稱（連線時 AI 自己報的 `clientInfo.name`，例：claude-ai、claude-code） | IP 位址 |
| 呼叫了哪一支工具、成功或失敗（錯誤碼） | 帳號、Email、任何個人資料 |
| 來源雜湊：IP 加上每天更換的秘密鹽做 HMAC，只用來算「當天有幾個不同來源」；隔天換鹽，同一個人不同天的雜湊對不起來，也不能反推 IP | |

- 只拿來看整體用量（每天幾個來源、幾次連線、各家 AI 的占比、哪些工具常用），不做個人分析、不提供給第三方。
- 防濫用的限流（每個 IP 每分鐘約 180 次工具呼叫；連線與列工具不計）由 Cloudflare 即時判斷，不另外保存 IP。

## 限制與免責

- 資料以全國法規資料庫與主管機關公告為準，每筆附出處、生效日與查證日，可以自己核對原文。
- 試算依公開參數估算，回完整算式；正式申報以你的記帳士、會計師與主管機關為準。
- 個案的延期、展延核准不在申報日曆裡。
- 查詢與試算結果不構成法律或稅務意見，也不代替申報。
- 每個 IP 每分鐘約 180 次工具呼叫（連線與列工具不計），超過大量時回 429，並寫明稍後再試。

## 怎麼驗證（驗證器與題目評測）

驗證分兩層，各管不同的事，兩層都要過：

- **驗證器**：把官方答案當標準，逐項比對試算工具算出的數字，不經過 AI。證明「計算機算得對」，每次改動都重跑。
- **題目評測**：拿真實會遇到的記帳與稅務、薪資題目，讓 AI 接上這個伺服器整題作答，再由另一個模型盲評。證明「AI 用得對」：記帳做法、判斷題、要先查哪支工具都答得對。

**三層可信度，不混在一起算**

1. **官方表格**：官方預先算好的金額表，一列就是一個官方答案，逐列要一模一樣。
2. **官方案例**：期望值來自官方試算工具、官方範例或條文例題的答案，用官方給的輸入重跑。
3. **自行設計**：期望值是我們依法源逐條算出的。它只證明「工具跟我們對法條的理解一致」，不是官方答案，所以跟官方案例分開計數，不併成一個通過率。

**抓到並已修正的差異**（完整紀錄在 [`DISCREPANCIES.md`](DISCREPANCIES.md)）

- **資遣費**：舊制年資已滿 25 年時，勞動部試算回 0 並寫「請改用退休金試算」；我們原本照公式算出一筆資遣費。現在照官方：不給舊制資遣費數字，回傳明確說明並改引退休金規定。
- **預告工資**：官方舉例「平均工資較一日工資高時，以平均工資計」；我們原本只用月薪除以 30，同一個例子少 2,000 元。已修正，並補進官方案例。
- **勞保級距**：部分工時、月薪 28,591 至 29,499 元的範圍，原本查不到投保級距；已補，並對官方 28 級逐級比對。
- **營所稅元以下進位**：財政部稅務入口網營利事業所得稅試算頁把應納稅額的元以下無條件捨去（課稅所得額 175,555 是 27,777；1,333,333 是 266,666），我們原本四捨五入、差 1 元。法規明文查不到，現在照官方試算頁捨去，並寫明依據。

**不支援的情境，直接講明**：每條規則的「已知不支援或待查」列在 [`COVERAGE.md`](COVERAGE.md)，工具遇到時回「不支援」或「待查」，不給猜的數字。例如：勞保被保險人不是「有一定雇主、參加就保的員工」（雇主、職業工會會員等約 20 類）與身心障礙減免、健保的身分別（工會會員、雇主、公務人員等）、財政部尚未公告的 115 年度基本生活費差額、非加值型營業稅的特種稅額、員工年資滿 25 年後的退休金。

- 不准為了讓案例通過而改期望值，也不准改程式去湊某一個案例；跟官方答案不一致時先查原因：我們錯就修程式、補測試，官方口徑需要裁定就寫進 `DISCREPANCIES.md`。

### 二、題目評測（接上 MCP 的 AI 整題作答）

驗證器證明工具算得對，不代表 AI 會先查對工具、記帳做法與判斷題也答得對。題目評測用「整題」來測：同一個模型回答同一批題目，分三組比答對率（效果總表就是這裡的結果）。

**怎麼測**

- **三組**：沒有 MCP（不能上網、沒有工具）、可上網（只有網頁搜尋）、有 MCP（只接這個伺服器）。
- **作答模型**：Claude Sonnet 5.5。每題開一個獨立的非互動 Claude Code，工作目錄是空的、不能讀檔，只給該組允許的工具。
- **評分**：另一位 Sonnet 5.5 當評分員，答卷只用代號、不知道是哪一組答的（盲評）。算錢題的「對」要金額、算式、法源三件都成立；其他題對 1 分、部分 0.5 分、錯或答不出 0 分。
- **標準答案**：每題附法源，信心中低的題目逐題複核；評分後發現標準答案有誤的，更正後受影響的題重跑重評。
- **保留組**：分「調整工具時看過」與「調整期間沒看過」兩組。保留組最後才跑，代表沒見過的題目，單獨列出。
- **全部對線上版實測**（2026 年 10 月 2、3 日），不含本機開發時的分數；題目、標準答案與逐題作答不公開。
- **只測了 Claude**；ChatGPT 等其他模型沒有實測。

### 兩者怎麼分工

- **驗證器**證明計算機算得對：每筆金額能追到官方答案，每次改動都重跑，改壞了就紅。
- **題目評測**證明 AI 用得對：會先查對工具、記帳做法與判斷題答得對，定期對線上版重跑。
- 兩者都要過：只有驗證器，不知道 AI 會不會用；只有題目評測，不知道數字有沒有被改壞。

## 每題用多少 token

這個伺服器的賣點是**答對率**，不是省 token。我們另外實測了用量，照實寫在這裡。

**做法**：30 題（記帳 8、查算 8、薪資 8、個人綜所稅 6），同一個模型（Claude Sonnet 5.5）三種方式各作答一次：**接這個伺服器**、**不接，只給 63 部法規全文檔與參數表讓它自己搜尋讀檔**、**只能上網**。用量取自 Claude Code 回報的實際 token；答對由另一個模型盲評。題數少、每組只跑一次，看量級，不是精確比較。

| 2026-10-15，30 題 | 接這個伺服器（0.5.0） | 自己搜尋法規檔 | 只能上網 |
|---|---:|---:|---:|
| 答對 | **29／30** | 21／30 | 25／30 |
| 每題 token 總量（含快取讀取），中位 | 71,054 | 50,594 | 14,112 |
| 每題成本（USD，API 牌價），平均 | $0.082 | $0.072 | $0.060 |

- **接這個伺服器的單題 token 並不是最少的**：它多花在把約 25 支工具的定義每一輪都帶進對話（約 16,500 token，有 prompt cache，以 10% 價計）。換來的是答對率：這 30 題 29 題對，另外兩種方式是 21 與 25 題。
- **不是整部法規塞進去**：AI 自己決定查哪幾條，平均每題約 3 次工具呼叫，沒有任何一題把整部法規讀進來。
- **0.5.0 比 0.3.0 省了一些**（同一批題目、同樣的重跑方式）：工具定義與大型回應預設精簡，單題成本約 −12%、新算的 token 約 −31%，單題 token 總量中位約 −10%，答對率不變（29／30）。要完整欄位（每個參數的出處與查證日、完整清單與目錄）時，在輸入帶 `detail: "full"` 或 `toc: true`，見[工具規格](TOOLS.md)。
- 其他用戶端（Claude 網頁與桌面版、ChatGPT）的用量沒有實測。
